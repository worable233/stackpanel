# 后台功能分组与插件页面归属

后台和用户中心的导航由内核路由与已启用插件的前端 manifest 合并生成。内核只负责身份、权限检查、激活状态和壳层布局；业务功能的分组、顺序、入口以及详情页的选中范围由插件声明。

## 页面关系

- **商店**：商店概览、商品、商品分类。
- **内容**：文章、页面、重定向、公告。
- **财务**：钱包、发票。
- **支持**：工单概览、工单。
- **API 中转**：概览、上游账号与定价、模型定价、API 密钥。
- **易支付**和**上游**：各自提供概览与配置/连接页面。
- 内核页面按用户与权限、站点、系统、开发者归类。

没有插件提供概览时，壳层不会生成一个假的概览入口；插件停用或当前用户没有路由权限时，对应菜单和页面也不会出现。

## 声明契约

插件的 `adminRoutes` / `accountRoutes` 中，导航元数据使用 `group`、`order` 和可选的 `activePaths`。`activePaths` 用于把商品编辑、工单详情等隐藏路由归属到已有功能入口。页面组件通过共享的 FeatureOverview 展示插件实际返回的统计与最近记录，数据读取失败显示不可用状态，不伪造数量。

壳层通过顶部横向导航展示功能分组和下拉菜单，不额外显示左侧二级导航；页面内容使用完整可用宽度。搜索、权限过滤和页面切换都使用同一份最终菜单，避免出现入口可见但页面无权访问的情况。

## 构建外部插件

开发 sibling 插件仓库时，可设置 `STACKPANEL_PLUGIN_SOURCES` 为其 `packages/plugins` 目录，再运行 `pnpm build:frontend`。外部同名插件源优先于内核内置副本，构建产物和 manifest 会写入当前运行时 `data`，生产构建不设置该变量即可使用内置插件。当前内核仓库只保留运行时必需的内置插件；其他插件（包括 `referral`）的源码位于 `StackPanel-plugins`，通过市场包安装或外部插件源接入。
