# 商店退款闭环 TODO

原则：任何不确定的支付、上游履约或实例处置状态均拒绝自动退款；目前实际退款目的地只支持 StackPanel 钱包，绝不把钱包入账描述为支付渠道原路退回。每项实施后逐项打勾并记录验证。

## 后端闭环

- [ ] 增加持久退款申请记录与状态机：待审核、已拒绝、退款中、已退至钱包、执行失败；申请人/审核人/原因/金额/时间可审计。
- [ ] 用户仅可为本人已付款且未退款的订单申请，验证累计可退金额；已申请/处理中金额占用额度防并发超退。
- [ ] 管理员列表、详情、拒绝和批准路由均校验权限、订单归属、状态与乐观锁；重复批准仅执行一次。
- [ ] 钱包退款按退款申请唯一 ID 幂等入账；部分退款累计正确，全部退完才终结订单，旧订单无字段时兼容为 0。
- [ ] 对账单明确实际入账目的地为平台钱包；合作方预付/金额币种异常/订单状态异常拒绝。
- [ ] 对履约结果未知、开通中、运行中的实例阻止批准；不自动删除上游实例。失败申请可见原因并可安全重试，不重复入账。
- [ ] 全额续费/变配回滚纳入可靠恢复流程；回滚未确认前不对用户宣称退款全部完成，具备可重试记录。
- [ ] 用户申请、管理员审核、成功/失败站内通知可恢复投递；事务外副作用以持久状态驱动重试。
- [ ] 退款审计记录操作者、订单、申请、金额、币种、目的地、结果及原因，不记录敏感凭据。

## 界面体验

- [ ] 用户订单页提供退款申请入口、金额/原因、退款到钱包说明、申请进度和拒绝/失败原因；显示实际可退余额。
- [ ] 管理员提供退款审核列表与简明订单/服务/支付摘要，批准前显著展示“入平台钱包”、实例处置要求、申请金额及累计金额。
- [ ] 加载/重复提交/冲突/失败/成功反馈统一使用后台通知，窄屏可用并有空态。
